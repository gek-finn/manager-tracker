# Развёртывание Manager Tracker: общие требования

Это обобщённая инструкция для новой установки, а не описание действующего VPS. Не применяйте шаблоны поверх существующих конфигураций без обследования. В исходниках нет данных SSH-доступа, конфигурации владельца или клиентской базы. Адрес опубликованного экземпляра указан в README; публичных учётных данных нет.

## До установки

1. Проверьте ОС, Python, память, swap, свободный диск, нагрузку и слушающие порты. Шаблоны ориентированы на Ubuntu 24.04 и Python 3.12.
2. Найдите соседние приложения, занятые пути, сайты Nginx и механизм продления сертификатов. Не останавливайте чужие службы.
3. Выберите собственный домен и свободный loopback-порт. Домены и пути в шаблонах — примеры, их нужно согласованно адаптировать для своей установки.
4. Проверьте чистую установку `requirements-production.txt` и тесты на Linux в отдельном окружении. Windows `.venv` не переносится.

## Разделение файлов

Код размещается в отдельном каталоге release, постоянная SQLite — вне release, закрытая JSON-конфигурация — вне исходников и web-root. Служба работает от отдельного пользователя без прав root. Каталоги данных и резервных копий закрыты от посторонних. Копии на одном VPS не заменяют внешнее резервирование.

Серверные шаблоны: `manager-tracker.service`, `gunicorn.conf.py`, `nginx-http.conf`, `nginx-https.conf`, `manager-tracker-backup.service`, `manager-tracker-backup.timer`, `certbot-deploy-hook.sh`. До применения проверьте все пути, пользователя, порт, домен и зависимости.

## Конфигурация и запуск

- Используйте `server_tools.py setup` для интерактивной настройки собственного владельца: пароль вводится скрыто, хеш и случайный SECRET_KEY сохраняются в закрытом JSON. Точный синтаксис доступен через `python server_tools.py setup --help`.
- `server-config.example.json` содержит пустые секретные поля. Это образец, не готовая конфигурация. Настоящий `server-owner.json` никогда не включается в Git.
- `TRACKER_SERVER_CONFIG` указывает абсолютный путь закрытого JSON. Значения ключа и хеша не передавайте в аргументах команд или публичных логах. `.env.example` автоматически не загружается.
- До запуска workers примените миграции отдельной командой `server_tools.py migrate` с резервированием. Справка: `python server_tools.py migrate --help`. Не запускайте миграцию параллельно с приложением. Существующий механизм maintenance-lock исключает конфликт серверного обслуживания и worker.
- Производственный вход — `wsgi:application`, Gunicorn, один worker. Встроенный Flask-сервер и BAT предназначены для локальной работы.
- Gunicorn слушает только loopback. HTTPS обслуживает Nginx. Доверие `TRUST_LOCAL_PROXY` включается только для одного локального Nginx, перезаписывающего forwarded-заголовки; дополнительные прокси требуют отдельного анализа.
- Сначала подготовьте отдельный HTTP-сайт и получите сертификат; только затем включайте HTTPS-шаблон с существующими путями сертификатов. Не заменяйте общий nginx.conf или чужие сайты. Перед reload нужна успешная проверка Nginx.

## Данные и резервирование

Для знакомства создавайте новую синтетическую базу через `server_demo.py`, как описано в README. Старый `seed_demo.py` может копировать рабочую базу и не является обезличиванием.

`server_tools.py backup`, `verify`, `restore` используют существующие инструменты обслуживания SQLite. Изучите `--help` перед применением. Согласованные копии создаются через SQLite Backup API с проверкой целостности. Не копируйте только живой SQLite-файл без учёта журналов. Настройте закрытое внешнее хранение и проверьте восстановление на отдельном пути.

До обновления сохраните согласованную пару кода и базы. Для отката остановите только своё приложение, сохраните текущее состояние и восстановите совместимую версию кода и проверенную копию базы. Восстановление теряет изменения после момента выбранной копии; его нельзя выполнять автоматически поверх новых данных.

## Приёмка

Проверьте автозапуск после перезагрузки, настоящий HTTPS, ограничение Host, cookies и CSRF за реальным прокси, вход и выход, миграцию, резервирование и восстановление. `/health` подтверждает процесс, но не заменяет проверку данных. Убедитесь, что соседние службы продолжают работать. Применение шаблонов и публикация не входят в подготовку публичного репозитория.
