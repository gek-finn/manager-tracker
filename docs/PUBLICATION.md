# Подготовка публичного GitHub-набора

Целевой репозиторий: `gek-finn/manager-tracker`. Подготовка не создаёт репозиторий на GitHub, коммит или push и не меняет remote.

## Состав и проверка

Точный состав — [PUBLIC_FILES.txt](PUBLIC_FILES.txt). Список включает исходники, BAT/launcher без изменений, зависимости, тесты, HTML/CSS/JS, инструменты демоданных, серверные шаблоны без секретов, README и руководство. Старые отчёты этапов, локальные промпты и сведения конкретного сервера в публичный набор не входят.

На момент подготовки корень проекта не был Git-репозиторием. Истории, отслеживаемых файлов и remote не было; проверять прошлые коммиты в этой папке невозможно. Если исходники публиковались в другом репозитории, его история этим обследованием не охвачена.

В локальной папке есть закрытая конфигурация владельца, рабочая база и манифест, временные SQLite, резервные копии, логи, окружение и архивы. Они остаются локально, вне публичного списка и под исключениями `.gitignore`. Секретные значения и пользовательские записи в отчёты не выводятся.

В тестах есть намеренные фиксированные пароли и ключи. Они используются только для временных тестовых владельцев; хеши генерируются при выполнении. IP из тестовых диапазонов и loopback — заглушки. Пустые поля `.env.example` и `deploy/server-config.example.json` не являются секретами. Не используйте тестовые значения в реальной конфигурации.

Обобщённая `deploy/INSTALL.md` заменяет локальную инструкцию с параметрами конкретного VPS. Оригинал сохранён в исключённой папке backups. Сами конфигурации служб, BAT, база и локальная конфигурация владельца не изменялись. Публикация исходников не обновляет действующий сайт.

Автоматическое сканирование — дополнительная проверка, не математическое доказательство отсутствия любых приватных сведений. Перед коммитом нужен просмотр полного diff и списка staged-файлов. Чистая установка зависимостей и проверка фактического Linux/VPS не входят в подготовку исходников.

## Безопасный следующий шаг — только после разрешения владельца

1. Возьмите новый пустой каталог **вне рабочей установки**. Скопируйте туда только файлы из PUBLIC_FILES.txt либо распакуйте проверенный публичный архив. Не копируйте рабочую папку целиком, скрытые данные, базы или окружение.
2. Сверьте точный состав и контрольные суммы с манифестом, подготовленным рядом с архивом. Не используйте старый серверный ZIP: это другой набор без тестов и пользовательской документации.
3. Создайте Git-репозиторий только в этой чистой папке. До коммита проверьте `git status --short`, `git ls-files --cached` и `git diff --cached`. Не используйте принудительное добавление игнорируемых файлов. Не считайте `git add .` в рабочей установке безопасной заменой этому шагу.
4. Повторно просмотрите staged-файлы на секреты и приватные данные. `.gitignore` не убирает уже отслеживаемые файлы и не очищает историю. Если обнаружен действующий секрет, остановитесь: замените его там, где он используется, и согласуйте отдельный план очистки. Историю автоматически не переписывайте.
5. Решите вопрос лицензии. LICENSE пока отсутствует, лицензия не выбрана; не добавляйте её без решения владельца.
6. Только после отдельного разрешения создайте целевой репозиторий, выполните коммит и настройте remote **в новой чистой папке**. Если репозиторий уже существует, сначала проверьте его владельца, историю и remote; не заменяйте их вслепую. Затем отдельно разрешённая публикация.

Команды создания репозитория и отправки намеренно не выполнялись. Данные входа, SSH-ключи и секреты не нужно передавать в чат или размещать в GitHub. Для знакомства с приложением создавайте чистую базу через `server_demo.py`, а не копируйте рабочую; подробности в README.
