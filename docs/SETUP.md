# Manager Tracker

Учебное веб-приложение для контроля клиентских заявок и задач менеджеров. Python, Flask и SQLite; интерфейс на русском языке.

Проект создан по мотивам [опубликованного заказа FL.ru №5524183](https://www.fl.ru/projects/5524183/nastroit-kontrol-zayavok-i-zadach-menedjerov-v-amocrm.html). Это самостоятельная учебная реализация, а не заявление о выполнении заказа реальному клиенту. **Интеграция с amoCRM не реализована.**

Опубликованное приложение: **[manager.gilinsky.ru](https://manager.gilinsky.ru)**. Требуется вход владельца; публичных учётных данных нет. Логин и пароль не предоставляются в репозитории. Статус публикации сообщён владельцем; при подготовке исходников рабочий сайт не проверялся.

## Возможности

- Создание, просмотр, редактирование и удаление заявок с подтверждением.
- Справочник активных и неактивных менеджеров; независимые ответственные заявки и задачи.
- Задачи со сроками, переносом с причиной, результатом выполнения и отменой.
- Автоматическая первичная обработка новой заявки и задача контакта после фиксации КП.
- История действий, содержательная активность, причины контроля и совместные фильтры.
- Панель руководителя, неизменяемые ежедневные сводки и CSV текущей выборки или снимка.
- Вход одного владельца, CSRF-защита форм, HTML-экранирование и ограничение неверных попыток входа.

Подробные сценарии: **[руководство пользователя](USER_GUIDE.md)**.

## Локальный запуск на Windows

Нужен Python 3.10 или новее с поддержкой venv и SQLite. Локальная разработка и прежние проверки выполнялись на Python 3.12. Команды выполняются в папке проекта; они не предназначены для рабочего VPS.

1. Создайте отдельное окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Первоначально настройте владельца:

   ```powershell
   .\.venv\Scripts\python.exe setup_owner.py
   ```

   Придумайте собственные логин и пароль. Пароль вводится скрыто и должен содержать не менее 12 символов. Инструмент создаёт закрытый `instance/local-owner.json` с хешем пароля и случайным ключом сессии. Не публикуйте этот файл и не копируйте тестовые учётные данные в рабочую конфигурацию. Повторная настройка не перезаписывает существующий файл без явного действия; для знакомства с проектом замена владельца не нужна.

3. Дважды щёлкните **запуск.bat** либо выполните:

   ```powershell
   .\.venv\Scripts\python.exe app.py
   ```

   Локальная база создаётся при первом запуске. После готовности сервера открывается браузер: обычно `http://127.0.0.1:5000`, при занятом порте — `http://127.0.0.1:5002`. При занятости обоих портов запуск завершается с сообщением. Повторный запуск открывает уже работающий экземпляр. Для остановки нажмите Ctrl+C в консоли.

BAT не устанавливает пакеты и не обращается к PyPI: он выбирает готовую среду из `.venv`, системного `python` или `py -3`, проверяя зависимости в выбранном интерпретаторе. Установка выполняется отдельно, только первым шагом выше. Консоль работающего сервера оставляйте открытой.

`.env.example` — только перечень параметров, файл `.env` автоматически не загружается. Для простого локального запуска достаточно интерактивной настройки владельца. Данные хранятся в SQLite и сохраняются между запусками. Веб-сайт и локальная копия имеют разные базы и конфигурации.

## Безопасное знакомство на демонстрационных данных

**Не используйте копию рабочей базы для демонстрации или публикации.** В набор исходников базы не входят.

На новой локальной копии проекта после установки зависимостей и настройки владельца:

1. До запуска приложения создайте новую синтетическую базу на отдельном пути:

   ```powershell
   .\.venv\Scripts\python.exe server_demo.py --output instance/demo-public.sqlite3
   ```

2. Только в текущем окне PowerShell выберите её и запустите приложение:

   ```powershell
   $env:TRACKER_DATABASE = (Join-Path (Get-Location) 'instance/demo-public.sqlite3')
   .\.venv\Scripts\python.exe app.py
   ```

3. После остановки приложения уберите выбор демонстрационной базы:

   ```powershell
   Remove-Item Env:TRACKER_DATABASE
   ```

`server_demo.py` создаёт базу с нуля: 5 вымышленных менеджеров, 25 заявок, задачи и явно отмеченные синтетические события. Контакты используют example.com, настоящих телефонов нет. Рабочая база не читается; существующий файл не перезаписывается. Рядом создаётся манифест. Сроки рассчитаны относительно времени создания и со временем устаревают. В демобазе нет владельца, секретов и готовых сводок; вход использует вашу отдельную локальную конфигурацию.

Не меняйте выбор базы у уже работающего экземпляра. Используйте отдельную локальную копию и остановленное приложение, чтобы не попасть в ранее запущенный экземпляр.

### Важное предупреждение о старом seed_demo.py

Этот инструмент сохранён для совместимости и тестов. **Если вызвать его без `--database`, а демонстрационного файла ещё нет, он сначала копирует `instance/tracker.sqlite3` через Backup API**, затем дополняет копию демозаписями. Поэтому такая база может содержать все прежние клиентские сведения. С явным `--database` инструмент дополняет указанную существующую базу. Это не средство обезличивания. Для публичного знакомства используйте только `server_demo.py` по инструкции выше. Не загружайте ни одну сгенерированную SQLite-базу в GitHub.

## Тесты

После установки зависимостей:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Тесты используют временные базы и вымышленные записи. Фиксированные пароли и ключи в тестах — тестовые заглушки, не учётные данные опубликованного приложения. Хеши для тестов генерируются во время выполнения. Не используйте эти значения для своего владельца.

Проверки BAT выполняются только на Windows, запускают изолированные копии и перехватывают открытие браузера. На Linux Windows-сценарии пропускаются. Требуется доступ к локальным тестовым портам. Результаты старых прогонов не заменяют новую проверку конкретной среды; при подготовке публичного набора полный набор бизнес-тестов заново не запускался.

## Ограничения

- Один владелец, без регистрации пользователей и отдельных входов менеджеров. Сессия — 8 часов.
- Приложение фиксирует отправку КП, но не отправляет письма или документы.
- Нет интеграции с amoCRM, Telegram, внешней рассылки и фоновых уведомлений.
- Нет текстового поиска: используются фильтры. Списки без пагинации.
- Время приложения — фиксированное UTC+02:00, интервалы календарные, включая выходные.
- Сводка создаётся при первом успешном открытии панели за день; пропущенные дни не восстанавливаются.
- CSV не является полной резервной копией. Удаление заявки необратимо через интерфейс; старые снимки сохраняют сведения.
- SQLite и один серверный worker подходят для небольшого учебного проекта; высокая нагрузка и горизонтальное масштабирование не подтверждены.
- Встроенный сервер Flask предназначен для локальной работы. Для публикации нужны отдельная конфигурация, Gunicorn, HTTPS и резервирование.
- В шаблонах интерфейса сохранились подписи «Локальное приложение» и «Этап 6А»; они не отражают текущий статус публикации. Веб-данные хранятся на сервере приложения, а не на компьютере посетителя.
