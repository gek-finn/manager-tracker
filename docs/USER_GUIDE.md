# Руководство пользователя Manager Tracker №2

Адрес приложения: [https://manager.gilinsky.ru](https://manager.gilinsky.ru).

Руководство описывает функции этапов 1–6Б по актуальному коду и шаблонам. Все примеры вымышлены. Интервалы и пороги могут отличаться от значений по умолчанию, если владелец изменил настройки.

## 1. Назначение и ограничения

Manager Tracker — учебный проект для регистрации клиентских заявок, назначения ответственных и контроля следующих действий. Заявка описывает потребность клиента, задача — конкретный шаг с собственным ответственным и сроком.

- Интеграции с amoCRM нет.
- Фиксация коммерческого предложения (КП) не отправляет письмо или документ. Связь с клиентом выполняется вне приложения.
- Вход предусмотрен для одного владельца. Менеджеры — справочник ответственных, отдельных учётных записей у них нет.
- Внешней рассылки и фоновых уведомлений нет. Контроль пересчитывается при открытии или обновлении страниц.
- История помогает следить за работой, но не удостоверяет личность фактического исполнителя.

Основные разделы: **«Заявки»**, **«Менеджеры»**, **«Настройки задач»**, **«Панель руководителя»**, **«Ежедневные сводки»**.

## 2. Быстрый старт

1. Откройте сайт. Введите свои данные в поля **«Логин»**, **«Пароль»** и нажмите **«Войти»**.
2. Откройте **«Заявки»** → **«＋ Новая заявка»**.
3. Укажите клиента «Демо Север», описание «Нужна консультация по подбору услуги», статус **«Новая»**. При необходимости выберите менеджера. Контакт можно оставить пустым или указать вымышленный `demo-sever@example.com`.
4. Нажмите **«Сохранить»**. Откроется карточка с автоматически назначенными номером и датой создания.
5. Найдите **«Задачи»** → **«Открытые»** → **«Обработать новую заявку»**. По умолчанию срок этой автоматической задачи — через 2 часа после создания заявки.
6. Свяжитесь с клиентом вне приложения. У первичной задачи нажмите **«Выполнить»** и заполните **«Результат выполнения *»**.
7. В блоке **«Следующий шаг первичной обработки *»** выберите другую существующую задачу либо создайте новую с названием и сроком. Нажмите **«Сохранить»**.

Результат: первичная задача станет выполненной, результат появится в истории, следующий шаг останется открытым. Если работа окончена, вместо выполнения первичной задачи можно закрыть заявку: её открытые задачи отменятся.

## 3. Заявки

### Поля

| Поле | Правило |
| --- | --- |
| Номер и дата создания | Назначаются автоматически, в форме не редактируются. |
| «Клиент / компания *» | Обязательно, от 1 до 200 символов. |
| «Контакт клиента» | Необязательно: телефон или email, до 250 символов. Приложение само не связывается по этому контакту. |
| «Описание потребности *» | Обязательно, от 1 до 10 000 символов. |
| «Ответственный менеджер» | Необязательно; выбор из справочника или «Не назначен». |
| «Статус *» | Обязательно; значения перечислены ниже. |
| «Приоритет» | «Низкий», «Средний», «Высокий»; по умолчанию «Средний». |

Одни пробелы не заменяют обязательное содержание. Приоритет обозначает важность, но сам не меняет сроки, контроль или сортировку. Сроки задаются в задачах; отдельного редактируемого срока заявки нет.

### Статусы

| Статус | Смысл |
| --- | --- |
| «Новая» | Обращение зарегистрировано, его ещё нужно взять в работу. Для контроля возраст считается от первоначального создания. |
| «В работе» | Обращение обрабатывается; следующие действия отражайте задачами. |
| «Ожидает клиента» | Ожидаются сведения или решение клиента. Сроки и контроль продолжают действовать. |
| «КП отправлено» | Специальным действием зафиксирована уже состоявшаяся отправка предложения. |
| «Закрыта» | Текущая работа завершена; открытые задачи отменяются, текущие причины контроля не показываются. |

Любой статус, кроме **«Закрыта»**, считается активной заявкой. Ожидание клиента и отправка КП не приостанавливают сроки.

### Просмотр и редактирование

1. В списке нажмите **«Просмотр»**. Карточка покажет поля, контроль, задачи и историю без перехода к редактированию.
2. Нажмите **«Редактировать»**, исправьте поля и нажмите **«Сохранить»**.
3. Проверьте сообщение об успешном сохранении и новые значения.

Обычное редактирование не создаёт первичную задачу и не фиксирует новое КП. Впервые установить **«КП отправлено»** обычной формой нельзя. Уже установленный статус можно сохранить либо заменить другим доступным.

### Закрытие и повторное открытие

1. Нажмите **«Редактировать»**.
2. Выберите **«Закрыта»** в поле **«Статус *»**.
3. Нажмите **«Сохранить»**.

Все открытые задачи станут отменёнными с причиной **«Заявка закрыта»**. Выполненные задачи сохранятся. История останется для чтения; добавлять действия и менять задачи закрытой заявки нельзя.

Для повторного открытия измените статус на **«Новая»**, **«В работе»** или **«Ожидает клиента»** и сохраните. Отменённые задачи не открываются, новая первичная задача не создаётся. Создайте следующий шаг вручную. Возврат в «Новая» не обнуляет возраст заявки.

Можно сразу создать закрытую заявку: открытой автоматической задачи первичной обработки у неё не будет.

### Удаление

1. В списке нажмите **«Удалить»** или в карточке **«Удалить заявку»**.
2. Проверьте номер и клиента на странице подтверждения.
3. Нажмите **«Да, удалить заявку»** либо **«Отмена»**.

Удаляются заявка, её задачи и история. Корзины и отмены удаления через интерфейс нет. Менеджер из справочника не удаляется. Сохранённые сводки остаются: вместо ссылки на карточку показывается **«Исходная заявка удалена»**. Сведения могут также оставаться в ранее скачанных CSV.

## 4. Менеджеры и ответственные

### Справочник

1. Откройте **«Менеджеры»** → **«＋ Добавить менеджера»**.
2. Заполните **«Имя менеджера *»**, например «Демо Марина».
3. Нажмите **«Сохранить»**. Менеджер станет доступен для назначения.

Новое имя — от 1 до 100 символов, без повторения другого имени с учётом того, что регистр и пробелы по краям не различают имена. Номер помогает отличать похожие старые записи.

- **«Переименовать»** → новое имя → **«Сохранить»**: меняется текущее имя в связанных заявках и задачах. Имена, сохранённые в истории и сводках, остаются прежними.
- **«Отключить»**: менеджер становится неактивным, прежние назначения сохраняются.
- **«Включить»**: менеджер снова доступен для новых назначений.

Удаления менеджеров нет. Отключение не переназначает работу автоматически.

### Назначение

В форме заявки выберите **«Ответственный менеджер»** и сохраните. Новым ответственным можно назначить активного менеджера. Уже назначенного неактивного можно оставить при редактировании этой записи, заменить активным либо снять назначение. Назначить неактивного заново нельзя.

Ответственные заявки и задачи независимы: например, заявка назначена «Демо Марине», отдельная задача — «Демо Илье». Смена ответственного заявки обычно не меняет задачи.

Исключение: при назначении заявке активного менеджера открытая автоматическая задача первичной обработки, у которой ещё нет ответственного, получает этого менеджера. Уже выбранный ответственный задачи не заменяется. На остальные задачи исключение не распространяется. Назначение записывается в историю.

## 5. Задачи

Задачи находятся в карточке заявки, в разделе **«Задачи»**, группами **«Открытые»** и **«Выполненные и отменённые»**. Отдельного общего списка задач нет.

### Создать

1. В незакрытой заявке нажмите **«＋ Новая задача»**.
2. Заполните **«Название задачи *»** — от 1 до 200 символов.
3. Укажите **«Срок *»** во времени UTC+02:00.
4. Проверьте **«Ответственный менеджер»**. Изначально предлагается активный ответственный заявки; его можно заменить или оставить задачу без ответственного.
5. Нажмите **«Сохранить»**. Задача появится в открытых.

Срок обязателен. Прошедший срок допустим, но задача сразу будет просроченной. Отсутствующие или некорректные сроки могут встречаться в старых данных; намеренно вводить их не нужно.

### Изменить или перенести

- Название или ответственный: **«Редактировать»** → изменения → **«Сохранить»**. Неактивного текущего ответственного можно сохранить, заново назначить неактивного нельзя.
- Срок: **«Перенести срок»** → новый **«Срок *»** и **«Причина переноса *»** → **«Сохранить»**. Причина и изменение попадут в историю.

Пример причины: «Демо-клиент попросил связаться на следующей неделе».

### Выполнить или отменить

- Выполненная работа: **«Выполнить»** → **«Результат выполнения *»** → **«Сохранить»**. Для первичной обработки дополнительно нужен следующий шаг, см. раздел 6.
- Ненужное действие: **«Отменить»** → **«Причина отмены *»** → **«Сохранить»**.

Результат и причины обязательны: от 1 до 10 000 символов. Выполненные и отменённые задачи нельзя редактировать или открывать заново. Создайте новую задачу, если нужен новый шаг. Удаления отдельной задачи через интерфейс нет.

### Ближайшая открытая задача

Выбирается открытая задача с самым ранним корректным сроком, включая прошедший. При равных сроках — с меньшим номером. Выполненные и отменённые задачи не участвуют. Задачи без корректного срока не становятся ближайшими, но могут давать предупреждения контроля.

При закрытии заявки все её открытые задачи отменяются. Повторное открытие заявки их не восстанавливает.

## 6. Первичная обработка

**«Обработать новую заявку»** означает: проверить обращение, связаться с клиентом, записать результат и определить следующий шаг. Это срок первой обработки, а не завершения продажи.

Задача создаётся только при создании новой незакрытой заявки. Старым заявкам она задним числом не добавляется. Переименование автоматической задачи не отменяет её специальных правил.

### Использовать существующий следующий шаг

1. Нажмите **«Выполнить»** у первичной задачи.
2. Заполните **«Результат выполнения *»**.
3. В поле **«Как определить следующий шаг»** выберите **«Использовать существующую задачу»**.
4. В поле **«Существующая открытая задача с корректным сроком»** выберите другую задачу этой заявки.
5. Нажмите **«Сохранить»**.

Подходит только другая открытая задача этой заявки с корректным сроком. Прошедший срок тоже технически допустим, но для дальнейшей работы лучше определить реальный будущий срок. Выбранная задача не выполняется и не переносится автоматически.

### Создать следующий шаг

1. Заполните результат.
2. Выберите **«Создать новую задачу»**.
3. В блоке **«Новая задача (заполните только при выборе создания)»** заполните **«Название»**, **«Срок»**, при необходимости **«Ответственный»**.
4. Нажмите **«Сохранить»**.

Первичная задача выполняется одновременно с созданием следующей. Без результата или следующего шага приложение покажет ошибку и не выполнит исходную задачу. У обычных задач и задач из старого поля срока требования следующего шага нет.

**Клиент ответил:** результат «Обсудили потребность Демо Север, клиент ждёт подбор вариантов». Следующая задача «Подобрать варианты для Демо Север», срок через два дня.

**Клиент не ответил:** результат «Позвонил, клиент не ответил». Следующая задача «Повторно позвонить», срок на следующий удобный день в UTC+02:00. Рабочие дни приложение само не рассчитывает.

Если продолжать работу не нужно, закройте заявку через редактирование. Выполнять первичную задачу перед закрытием не требуется.

## 7. Коммерческое предложение

### Первая фиксация

1. Отправьте КП клиенту вне приложения.
2. Убедитесь, что заявка не закрыта и назначен активный ответственный.
3. В карточке нажмите **«Отметить отправку КП»**.
4. Заполните **«Комментарий о предложении *»** — от 1 до 2 000 символов. Например: «Для Демо Север отправлены два варианта услуги».
5. Отметьте **«Подтверждаю, что коммерческое предложение уже отправлено клиенту»**.
6. Нажмите **«Подтвердить отправку КП»**.

Результат: статус **«КП отправлено»**, одноимённое содержательное событие, открытая задача **«Связаться после отправки КП»**. Задача назначается ответственному заявки; по умолчанию её срок через 24 календарных часа после фиксации.

Без активного ответственного действие не сохранится. Назначьте активного менеджера и откройте актуальную форму заново.

### Повторная отправка

Если действительно отправили новое КП, в статусе **«КП отправлено»** нажмите **«Отметить повторную отправку КП»**. Введите новый комментарий, снова подтвердите состоявшуюся отправку и нажмите **«Подтвердить отправку КП»**.

Каждая намеренная отправка создаёт своё событие и одну новую задачу контакта. Предыдущая открытая автоматическая задача контакта отменяется с причиной **«Заменена задачей после повторной отправки КП»**. Обычные и выполненные задачи не меняются. Замена действует также при новой фиксации после перехода заявки из статуса КП в другой статус.

Повтор того же запроса или обновление страницы результата не создаёт дублей. Но новая форма с новым подтверждением — отдельная намеренная отправка. Не используйте её для простого исправления карточки. Обычное сохранение заявки со статусом КП не создаёт нового события отправки или задачи.

## 8. История и содержательная активность

В карточке откройте **«История действий»**. Новые события показаны раньше старых.

1. В незакрытой заявке найдите **«Добавить действие»**.
2. Выберите **«Тип действия»**: **«Звонок»**, **«Сообщение клиенту»**, **«Комментарий»**.
3. Заполните **«Результат или комментарий *»**, от 1 до 2 000 символов.
4. Нажмите **«Добавить действие»**. Запись получит текущее время UTC+02:00.

Ввод задним числом недоступен. Закрытая заявка допускает только просмотр истории. Редактирования и удаления отдельных событий нет.

Приложение само записывает создание и изменения заявки, смену ответственного или статуса, действия с задачами и фиксацию КП. Сведения в событии относятся к моменту действия: переименование менеджера не переписывает старое имя.

**Обновляют последнее содержательное действие:** создание заявки, звонок, сообщение клиенту, комментарий, выполнение задачи, фиксация отправки КП.

**Не обновляют:** просмотр, изменение полей, статуса или ответственного, создание или редактирование задачи, перенос срока, отмена задачи, изменение настроек, закрытие и повторное открытие заявки, техническое подключение журнала.

**«Журнал подключён»** — начало ведения истории старой заявки. Это не контакт с клиентом и не подтверждение даты первоначального обращения. Предыдущие действия не восстановлены. Нехватка достоверных событий не равнозначна доказанной длительной неактивности.

Отдельный исполнитель события не фиксируется. Назначенный менеджер не доказывает, кто нажал кнопку. История не заменяет персональный аудит работы сотрудников.

## 9. Сроки и контроль

Все сроки и расчёты используют **UTC+02:00**, независимо от часового пояса устройства. Интервалы — календарные часы, включая ночи, праздники и выходные. Ровно на границе срока просрочки ещё нет; она начинается после него.

### Состояние срока заявки

| Отметка | Значение |
| --- | --- |
| «Закрыта» | Заявка закрыта; текущие сроки не оцениваются. |
| «Просрочена» | Хотя бы одна открытая задача с корректным сроком просрочена. |
| «Некорректный срок» | Подтверждённой просрочки нет, но есть открытая задача с нераспознаваемым сроком. |
| «В срок» | Нет просрочки и некорректных сроков, есть открытая задача с корректным непросроченным сроком. |
| «Срок не назначен» | Нет открытых задач с корректным сроком и нет некорректного непустого срока. |

Состояние срока отличается от причин контроля. Будущая задача и другая задача без срока могут дать одновременно **«В срок»** и **«Задача без срока»**.

### Подтверждённые проблемы

| Причина | Условие и действие |
| --- | --- |
| «Нет ответственного» | Не выбран менеджер заявки. Назначьте ответственного. Неактивный назначенный менеджер не считается отсутствующим. |
| «Не взята в работу» | Статус «Новая» сохраняется дольше порога от первоначального создания. Проверьте обращение и установите соответствующий работе статус. |
| «Нет следующей задачи» | У незакрытой заявки нет открытых задач. Создайте следующий шаг или закройте завершённую заявку. |
| «Задача без срока» | Хотя бы у одной открытой задачи срок пустой. Уточните его через «Перенести срок» с причиной. |
| «Просрочена задача» | Открытая задача с корректным сроком просрочена. Выполните с результатом, обоснованно перенесите либо отмените ненужное действие. |
| «Давно нет активности» | После последнего достоверного содержательного действия прошло больше порога. Проверьте работу и запишите реальный результат. |

### Предупреждения о данных

| Причина | Значение |
| --- | --- |
| «Нет данных об активности» | Нет достоверного содержательного действия либо повреждённые сведения мешают определить последнее. Это не доказанная просрочка активности. |
| «Некорректный срок задачи» | Непустой срок открытой задачи нельзя распознать; сам по себе он не доказывает просрочку. |
| «Некорректная дата создания» | Дата не распознаётся или находится в будущем; возраст заявки нельзя надёжно оценить. |
| «Некорректные данные события» | Сведения события непригодны для расчёта, например неизвестен тип или дата находится в будущем. |

Предупреждения требуют проверки исходных сведений. За исправлениями, недоступными обычной формой, обратитесь к администратору. Автоматического исправления данных нет.

Причин у одной заявки может быть несколько: и проблемы, и предупреждения. Будущая задача не снимает просрочку другой. **Комментарий обновляет активность, но не выполняет задачу и не переносит её срок**, поэтому просрочка остаётся. У закрытой заявки текущих причин контроля нет.

## 10. Поиск нужных записей с помощью фильтров

Текстового поиска нет. В разделе **«Заявки»** доступны:

| Фильтр | Условия |
| --- | --- |
| «Область» | «Все заявки», «Активные», «Закрытые». |
| «Ответственный» | «Все», «Не назначен», конкретный менеджер. Неактивные с назначениями тоже могут присутствовать. |
| «Статус» | «Все» или один из пяти статусов. |
| «Просрочка» | «Все», «Только просроченные», «Без просрочки». |
| «Контроль» | «Все», «Есть проблемы», «Требуют проверки данных», «Без замечаний» либо одна из причин раздела 9. |

1. Выберите условия и нажмите **«Применить»**.
2. Отобразятся заявки, отвечающие всем условиям одновременно.
3. Для свежего расчёта с теми же условиями обновите страницу браузера.
4. Для полного списка нажмите **«Сбросить»**. В пустой выборке есть также **«Сбросить фильтры»**.

Пример: «Область» → «Активные», конкретный «Ответственный», «Контроль» → «Просрочена задача» покажут активные заявки этого менеджера с просроченной задачей.

Условия сохраняются в адресе и после обновления страницы. Несовместимые условия, например «Закрытые» и «Новая», дадут пустую выборку. Сообщение **«По выбранным условиям заявки не найдены»** не означает удаление данных.

**«Без просрочки»** не равно **«Без замечаний»**: туда могут попасть закрытые заявки и заявки без срока. Если срок некорректен и другая задача не подтверждает просрочку, заявка не входит ни в просроченные, ни в выборку без просрочки. **«Без замечаний»** — только незакрытые заявки без проблем и предупреждений.

В общем списке новые номера идут первыми. Фильтра и сортировки по приоритету нет.

Если таблица шире экрана, прокручивайте её вправо внутри самой таблицы: нижней горизонтальной полосой, жестом на сенсорной панели или, где браузер поддерживает, **Shift + колёсико мыши**. На телефоне проведите по таблице вбок.

## 11. Панель руководителя

Откройте **«Панель руководителя»**. Время расчёта указано на странице. Кнопка **«Обновить»** получает свежие значения.

| Показатель | Заявки |
| --- | --- |
| «Активные» | Все незакрытые. |
| «Новые» | Со статусом «Новая». |
| «Есть проблемы» | С подтверждёнными проблемами. |
| «Нет ответственного» | Без менеджера заявки. |
| «Не взяты в работу» | Новые дольше порога. |
| «Нет следующей задачи» | Без открытых задач. |
| «Есть задача без срока» | С открытой задачей без срока. |
| «Есть просроченная задача» | С просроченной открытой задачей. |
| «Давно нет активности» | С превышением порога достоверной активности. |
| «Требуют проверки данных» | С предупреждениями о данных. |

Все показатели относятся к незакрытым заявкам. Группы пересекаются; внутри каждой заявка считается один раз. Складывать показатели для общего итога нельзя. Проблемы и предупреждения тоже могут пересекаться.

Нажмите блок показателя для перехода к соответствующей выборке. В таблице **«Требуют внимания»** каждая проблемная заявка показана один раз со всеми причинами: сначала просроченные задачи, затем другие проблемы, затем только предупреждения. Внутри этих групп новые номера идут первыми.

Панель пересчитывается, сводка фиксирует прежний момент. Ссылка **«Сегодняшняя сводка · …»** ведёт к снимку. Его показатели могут отличаться от текущих уже сегодня.

## 12. Ежедневные сводки

Первое успешное открытие панели за календарную дату UTC+02:00 сохраняет одну сводку: десять показателей, пороги и строки таблицы контроля на один момент. Время формирования фактическое, не обязательно начало дня.

- Повторное открытие в тот же день не перезаписывает снимок.
- Сохраняется и пустая сводка.
- Если панель в какой-то день не открывали, сводки нет. Задним числом она не восстанавливается.
- Изменения заявок, задач, менеджеров и настроек не меняют старые снимки.
- Другие страницы и CSV сами сводку не создают.
- Нет внешней рассылки, редактирования и удаления сводок через интерфейс.

1. Откройте **«Ежедневные сводки»**. Новые даты сверху.
2. Нажмите **«Просмотр»** у даты.
3. Проверьте время, показатели, пороги и строки. Надпись **«Сохранённый снимок, данные не обновляются»** отличает его от текущей панели.

Показатели снимка не ведут в сегодняшние выборки. **«Открыть текущую карточку»** ведёт к нынешнему состоянию заявки, не к исторической карточке. После удаления заявки показано **«Исходная заявка удалена»**, сохранённая строка остаётся.

Для пустого снимка: **«На момент формирования заявок, требующих внимания, не было»**. Это не обязательно означает отсутствие всех заявок. Если сводок пока нет, первая появится после открытия панели.

При ошибке сохранения сводки текущая панель может оставаться доступной. Откройте её повторно позже и проверьте ссылку на сегодняшнюю сводку; при повторении ошибки обратитесь к администратору.

## 13. CSV и Excel

### Текущая выборка

1. Откройте **«Заявки»**, выберите фильтры и нажмите **«Применить»**.
2. Проверьте результат и нажмите **«Скачать CSV»**.
3. Откройте файл в Excel или другой программе таблиц.

Выгружается вся отфильтрованная выборка в текущем порядке: номер, дата создания, клиент, контакт, статус, приоритет, ответственный и его состояние, активность, ближайшая задача, её срок, состояние срока, причины контроля. Расчёт выполняется на момент выгрузки, а не первоначального просмотра списка.

### Сохранённая сводка

Нажмите **«Скачать CSV»** в списке сводок или на странице снимка. Используются сохранённые значения, включая дату и время формирования. **Сводка не пересчитывается при экспорте**, даже если исходные заявки изменены или удалены. CSV содержит строки контроля; показатели и пороги смотрите на странице сводки.

### Если Excel отображает неудобно

- Формат — UTF-8 с BOM, разделитель `;`. Если всё попало в один столбец или искажены русские буквы, используйте **«Данные» → «Из текста/CSV»**, UTF-8, разделитель «точка с запятой». Названия пунктов зависят от версии Excel.
- CSV не хранит ширину столбцов. Раздвиньте столбец за правую границу заголовка или дважды щёлкните по ней для подбора ширины.
- **########** часто означает, что столбец узок для даты или числа. Сначала расширьте его; если не помогло, проверьте формат ячейки и исходное значение в строке формул. Само отображение не доказывает повреждение данных приложения.
- Даты записаны однозначно, с часовым поясом там, где применимо. При импорте можно выбрать текстовый формат для сохранения исходной записи.
- Опасные формулы из пользовательского текста обезвреживаются при экспорте; иногда виден начальный апостроф. Это защитное представление, исходные записи не меняются.
- Пустая выборка даёт заголовки без строк данных.

CSV не является полной резервной копией; обратного импорта через интерфейс нет. Файлы и сводки содержат клиентские сведения: храните их безопасно и не публикуйте без необходимости.

## 15. Вход и выход

1. Откройте сайт, введите выданные вам данные и нажмите **«Войти»**.
2. После работы нажмите **«Выйти»**, особенно на общем компьютере.

Сессия действует **8 часов с момента входа**. Работа в приложении срок не продлевает. После истечения войдите снова. Если сохранение отклонено из-за окончания сессии, операция не выполнена: после входа откройте актуальную карточку или форму, проверьте состояние и повторите действие.

После **5 неверных попыток за 15 минут** вход с того же сетевого адреса блокируется на **15 минут**. При сообщении **«Слишком много попыток входа»** подождите и проверьте ввод; не повторяйте запросы непрерывно. В общей сети лимит может затронуть нескольких пользователей этой сети.

Нет регистрации, отдельных входов менеджеров, гостевого доступа и восстановления пароля через почту. Для смены или восстановления пароля владелец обращается к администратору. Кнопки смены пароля в интерфейсе нет. Передача данных входа другим людям не позволит истории различать исполнителей.

При сообщении об устаревшей форме обновите страницу и откройте действие заново. Несохранённый текст может потребоваться ввести повторно: перед обновлением сохраните важный текст для себя в безопасном месте. После неоднозначной ошибки сначала проверьте карточку и историю, прежде чем подтверждать отдельное действие через новую форму.

## 16. Ежедневный порядок и типичные вопросы

### Короткий порядок

1. Войдите, откройте **«Панель руководителя»**. Первое открытие за день сохранит сводку на этот момент.
2. Проверьте просроченные задачи, отсутствие ответственных, затянувшиеся новые заявки и остальные причины. Предупреждения о данных разбирайте отдельно.
3. Откройте нужные заявки, выполните реальные контакты и запишите результаты.
4. Для каждой незакрытой заявки определите следующий шаг со сроком и ответственным.
5. Переносите сроки с объяснением, отменяйте ненужные задачи, закрывайте завершённые заявки.
6. Нажмите **«Обновить»** на панели. При необходимости выгрузите текущую выборку или сводку.
7. Нажмите **«Выйти»**.

### Вопросы

**Почему после комментария осталась просрочка?** Комментарий меняет активность, но не задачу. Выполните её с результатом, обоснованно перенесите либо отмените ненужное действие.

**Почему нельзя выполнить первичную задачу?** Нужны результат и следующий шаг с корректным сроком. Выберите существующую задачу или создайте новую в этой форме. Если работа окончена, закройте заявку.

**Почему задача осталась у прежнего менеджера?** Ответственные заявки и задачи независимы. Переназначьте открытую задачу через «Редактировать». Исключение — только ещё незакреплённая открытая первичная задача.

**Почему неактивный менеджер виден?** Отключение сохраняет назначения. Замените его при необходимости. Само отключение не создаёт причину «Нет ответственного».

**Почему нельзя просто выбрать статус КП?** Специальное действие сохраняет комментарий об отправке и создаёт задачу контакта.

**Почему сводка отличается от панели?** Сводка отражает первый успешный просмотр панели за дату; панель пересчитывается сейчас.

**Почему нет вчерашней сводки?** Если панель вчера не открывали, снимок не создавался. Задним числом он не восстанавливается.

**Почему сумма показателей больше числа заявок?** У одной заявки несколько причин, группы пересекаются.

**Почему после повторного открытия нет открытых задач?** При закрытии они отменились и не восстанавливаются. Создайте новый шаг.

**Почему заявка исчезла из таблицы?** Нажмите «Сбросить» и проверьте фильтры. Новое состояние могло вывести заявку из текущей выборки.

**Можно вернуть удалённое?** Через интерфейс — нет. По вопросам восстановления обратитесь к администратору; резервная копия не является пользовательской кнопкой отмены. История и сводки отдельно не редактируются.

**Приложение само позвонит или напомнит по почте?** Нет. Связь с клиентом и отправка КП выполняются вне приложения, задачи проверяются в интерфейсе.
